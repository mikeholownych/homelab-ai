## 1. Proposed v1.0.0 Product Contract

### 1.1 Intended Product Identity
`homelab-ai` (`aihost`) is an **enterprise-grade, configuration-as-code local AI inference appliance**. It delivers sovereign, high-throughput, OpenAI-compatible LLM serving tailored for agentic coding and software engineering workflows. It is engineered to operate on dedicated workstation hardware equipped with dual Intel Arc Pro B65 GPUs under strict hardware isolation, bounded reasoning budgets, cryptographic evidence accounting, and zero-trust security controls.

### 1.2 Supported Users & Personas
1. **Developer / Coding Agent Persona**: Autonomous coding assistants (e.g., OpenCode, Antigravity, Claude Code, Nexus) connecting remotely over authenticated TLS to consume OpenAI-compatible streaming chat completions, tool calling, and token counting.
2. **Platform Operator Persona**: Systems administrator managing host configuration, model qualification, safe rollbacks, OS tuning, and scheduled reconciliation via Ansible and Vault.
3. **Observability & SRE Persona**: Site reliability engineer monitoring real-time VRAM allocation, GPU thermals, queue latency, error budgets, and distributed traces in Grafana and on the local TTY1 terminal console (`vllm-top`).

### 1.3 Supported Workloads
- **High-Throughput Engineering Lead Route**: Unbounded-generation prevention with 8192 token answer allowances; fast speculative or standard decode using `Qwen3.6-35B-A3B-UD-Q4_K_M` (GPU 0). Reasoning disabled by default for rapid interactive code editing.
- **Deep Architectural & Debug Reasoning Route**: Complex refactoring, architecture review, and post-failure escalation using `Qwen3.8-Flash-Next-GSQ-RCO-IQ1_M` (GPU 1) with an evidence-backed 4096-token reasoning budget.
- **Opt-In Lead Reasoning Route**: Model alias `engineering/lead-reasoning` routing to GPU 0 with explicit 8192-token reasoning enabled.
- **Dynamic Queueing & Admission**: Priority and fair-share scheduling, client-disconnect cancellation, backpressure, and graceful HTTP 429 overload shedding.

### 1.4 Certified Hardware & Deployment Profiles
- **Certified v1.0.0 Host Profile**: Single-node Dell Precision 5820 Tower (`d5820_dual_b65`), Intel Xeon W-2123, 32 GB ECC DDR4, dual ASRock Intel Arc Pro B65 Creator 32 GB GPUs, PCIe Gen3 x16, dual NVMe SSDs with LVM storage pool, Ubuntu 26.04 LTS (`resolute`).
- **Deferred Post-v1 Profile**: Lenovo ThinkStation P620 (`p620_dual_b65`), AMD Threadripper PRO 3945WX, 48 GB DDR4.

### 1.5 Operating & Support Boundaries
- **Remote-Origin Only**: All inference workloads must originate from remote allowlisted client CIDRs (`10.0.8.95/32`). Workload generation originating from the inference host itself is blocked (HTTP 403).
- **Gateway-Only Access**: Inference workers listen exclusively on `127.0.0.1` and accept TCP traffic only from the dedicated `aihost-gateway` service identity (UID 995). Direct local connections from root or standard users are dropped by nftables.
- **Single Secret Authority**: HashiCorp Vault via AppRole authentication. No plaintext keys in Git, environment files, or Ansible Vault.
- **Independent Operational Viability**: The appliance must remain fully functional, observable, and release-qualified independently of any client (such as Nexus). Client integrations must not substitute for standalone platform acceptance.
