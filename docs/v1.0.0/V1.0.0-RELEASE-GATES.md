## 3. Evidence Retention & Auditing Requirements

1. **Persistent Evidence Chaining**: Every inference completion accepted by `orchestrator_gateway` must append an anchor record to `/var/lib/aihost-gateway/evidence-chain.jsonl`.
2. **Reconciliation Stamp**: The controller must write `/var/lib/local-ai/evidence/reconcile-last.json` upon every hourly convergence run, carrying the exact Git commit SHA and execution status.
3. **Machine Validation Records**: Every deployment or hardware change must be accompanied by a fresh `validation.json` generated by `playbooks/validate.yml` and retained in `evidence/ai-5820-01/`.

---

## 4. Human-Only Actions & Prerequisite Approvals

The following steps require direct operator authorization and cannot be automated:
1. **Operator Approval of Fleet De-Scoping**: Formally approve scoping v1.0.0 strictly to `ai-5820-01` and moving `ai-p620-01` to post-v1 uncommissioned backlog.
2. **Production Gateway Deployment Window**: Authorize the maintenance window to promote gateway release `b72a4f5` and restart `aihost-orchestrator-gateway.service`.
3. **Vault Root/Unseal Key Storage**: Physical custody and out-of-band management of Vault server unseal keys.
4. **Final Release Tag Signing**: GPG signing and pushing of git tag `v1.0.0`.

---

## 5. Explicit Criteria for Claiming v1.0.0 Readiness

`homelab-ai` may be declared **v1.0.0 RELEASE READY** if and only if:
1. All 5 release blockers (`F-01` through `F-05`) have their corresponding implementation plans executed and verified.
2. Every item in the Go/No-Go checklist is marked **PASS** with attached machine-readable evidence.
3. `make lint`, `make syntax`, and targeted tests pass with zero errors.
4. The controller snapshot runner is synchronized with git HEAD, and steady-state hourly reconciles produce 0 changes.
5. The repository owner signs off on the release candidate report.
