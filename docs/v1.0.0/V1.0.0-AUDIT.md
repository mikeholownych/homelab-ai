## 1. Executive Summary & Readiness Verdict

### Readiness Verdict: **`V1_0_0_NOT_DEMONSTRATED_CONTRADICTED_BY_BLOCKERS`**

While the `homelab-ai` platform exhibits sophisticated low-level engineering—including a production-proven dual-GPU Alchemist Arc Pro B65 inference appliance on Ubuntu 26.04 (`ai-5820-01`), strict Level Zero hardware binding, bounded reasoning budgets, dynamic queue admission control, OTLP distributed tracing, and cryptographic evidence chaining—**the repository in its current state cannot be certified as defensibly v1.0.0 ready.**

Readiness is contradicted by **five critical release blockers (Severity 1)**:
1. **Live Production vs. Controller Gateway Release Divergence**: The repository `main` branch includes Phase 4 gateway advancements (ASGI engine, zero-downtime hot reload, dual circuit breakers, semantic caching, watchdog self-healing; commit `b72a4f5`), bumped in inventory to `t5820-gateway-b72a4f5`. However, the live appliance `ai-5820-01` runs legacy release `t5820-gateway-6a3a52e`. This divergence exists because the controller's hourly scheduled reconciliation systemd timer (`aihost-reconcile.service`) executes from an isolated snapshot at `/home/mike/.local/share/aihost/reconcile/snapshot` pinned to historical commit `f169cbbd896e` (Oct 11 2026). The repository codebase is neither deployed nor reconciled with production.
2. **`make lint` CI Gate Failure**: Clean-checkout CI validation fails immediately on `make lint`. Specifically, `yamllint .` fails on `observability/prometheus/rules/aihost.rules.yml:186` (empty lines) and `roles/orchestrator_gateway/defaults/main.yml:89` (line length > 120 chars); `ansible-lint .` fails with 3 fatal violations including `var-naming[no-role-prefix]` on `_historical_gateway_releases` at `roles/orchestrator_gateway/tasks/main.yml:350`.
3. **Core Architectural Documentation Contradiction**: `README.md`, `docs/architecture.md`, `roles/vllm_xpu/`, and multiple runbooks publish an obsolete system architecture stating that vLLM 0.7.3 TP=2 is the primary serving runtime, with llama.cpp as fallback. In reality, vLLM is completely retired on production (`ai-5820-01`), and two independent llama.cpp SYCL TP=1 instances (one per Arc Pro B65 GPU) serve production via the `orchestrator_gateway`. A new operator cannot deploy or understand the platform from current documentation.
4. **Phantom Multi-Node Fleet Member (`ai-p620-01`)**: `inventory/production/hosts.yml` and `README.md` declare a two-node production fleet consisting of `ai-p620-01` (Lenovo ThinkStation P620) and `ai-5820-01` (Dell Precision 5820). However, `inventory/production/host_vars/ai-p620-01.yml` contains `ansible_host: CHANGE_ME`, the hostname does not resolve in DNS or `/etc/hosts`, and the host has never undergone physical commissioning or software bootstrap. Multi-node fleet operation is unverified.
5. **Orphaned Vault Server Automation & Undefined Control Plane Boundary**: `playbooks/vault-server.yml` specifies `hosts: vault_servers`, but no `vault_servers` group exists in `inventory/production/hosts.yml`, generating Ansible warnings on syntax checks. Vault server provisioning, sealing, unsealing, and raft storage lifecycle are detached from production automation, while production relies on an external Vault instance whose disaster recovery and initial setup remain unproven in code.

## 5. In-Depth Component Audit

### 5.1 Architecture & Interfaces
- **Gateway Responsibilities**: The `orchestrator_gateway` operates as an intelligent reverse proxy and policy gate between remote developer clients (OpenCode, Nexus, operator CLI) and local inference workers. It exposes OpenAI-compatible REST endpoints (`/v1/models`, `/v1/chat/completions`, `/v1/tokenize`) alongside administrative inspection endpoints (`/health`, `/metrics`, `/v1/admin/routes`).
- **Engine Adapters**: Adapters in `orchestrator_runtime/engines.py` abstract backend differences between llama.cpp and vLLM. Capacity tracking uses live engine inspection (`/props`, `/slots`, `/metrics`) rather than static configuration files.
- **Routing & Capabilities**: Routing is evaluated sequentially through `orchestrator_gateway_routes`. The default route matches all unclassified traffic and routes to the `lead` pool (`Qwen3.6-35B-A3B`) with reasoning disabled. Demanding tasks (task classes `review`, `architecture`, `debug-hard`, or client retry `attempt >= 2`) route to the `deep` pool (`Qwen3.8-Flash-Next-GSQ-RCO-IQ1_M`) with 4096-token reasoning enabled. Model aliases (`engineering/lead`, `engineering/deep`, `engineering/lead-reasoning`) bypass the rule table.
- **Admission Control & Queueing**: Inflight requests are governed by adaptive capacity limits (AIMD backoff on error). Requests exceeding available slots enter a priority/fair-share FIFO queue with strict timeouts (HTTP 504 on deadline expiration, HTTP 429 when queue capacity is reached).
- **Streaming & Disconnection**: Implements native Server-Sent Events (`text/event-stream`). Streaming response generation is bound to client TCP socket liveness; client disconnection cancels worker generation, preventing compute starvation.

### 5.2 Provisioning & Lifecycle
- **Clean Bootstrap**: `playbooks/bootstrap.yml` initializes Python 3.12, base packages, time synchronization, user identities, and SSH hardening.
- **Convergence & Idempotency**: `playbooks/site.yml` and `playbooks/inference.yml` enforce desired state. Verification via `scripts/check-tuning-idempotency` and `make syntax` ensures repeatable, byte-stable passes.
- **Reconciliation Snapshot Runner**: `scripts/run-ansible-snapshot` locks execution via non-blocking `flock` and validates repo dirty states, preventing race conditions or partial executions.
- **Rollback Architecture**: Component rollback is documented in `docs/rollback.md` and drilled live on `ai-5820-01` (proven on 2026-10-09 during `Q-FINAL` drill). Inventory maintains verified capability evidence for the rollback target (`Qwen3.5-27B`).

### 5.3 Inference & Hardware Resource Management
- **Hardware Architecture**: Dell Precision 5820 Tower with Intel Xeon W-2123 (4 cores / 8 threads) and 32 GB ECC DDR4. Two ASRock Intel Arc Pro B65 Creator 32 GB GPUs. PCIe Gen3 x16 link negotiation on Intel C422 chipset.
- **Serving Configuration**:
  - Worker 1 (GPU 0): `Qwen3.6-35B-A3B-UD-Q4_K_M.gguf` (context 65536, reasoning budget 8192, cpuset `0,1,4,5`).
  - Worker 2 (GPU 1): `Qwen3.8-Flash-Next-GSQ-RCO-IQ1_M` (context 65536, reasoning budget 4096, cpuset `2,3,6,7`).
- **VRAM Headroom**: Per-device memory consumption is isolated to 27.5 GB, leaving ~4.5 GB headroom per 32 GB card for Level Zero command buffers and KV cache.
- **Thermal & Power Budgets**: Benchmarking guardrails enforce 950 W PSU capacity and 200 W per-GPU TDP ceiling. Hwmon textfile collectors feed real-time thermals into Prometheus with automated thermal abort thresholds at 85°C.

### 5.4 Security & Secrets
- **Secret Authority**: HashiCorp Vault is the sole authority. No secrets are stored in Git or Ansible Vault.
- **Credential Delivery**: Secrets are delivered via systemd `LoadCredential=` into private `/run/credentials/` namespaces. Credentials are mode `0400` root-owned and read-only.
- **Zero-Trust Network Isolation**:
  - Gateway runs as dedicated service identity `aihost-gateway` (UID 995).
  - Workers bind strictly to `127.0.0.1`.
