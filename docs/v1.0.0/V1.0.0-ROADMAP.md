## 1. Roadmap Architecture & Critical Path

The path to defensible v1.0.0 maturity requires completing five release blockers, eliminating configuration drift between the repository and production, and achieving 100% clean CI verification. 

Work is structured into six dependency-ordered milestones (M0 through M5):
- **M0: Repository Hygiene & CI Integrity Containment** (Immediate security and linting fixes)
- **M1: Fleet Topology & Hardware Scope Decoupling** (Decouple uncommissioned `ai-p620-01`)
- **M2: Gateway Release & Controller Reconciliation Alignment** (Deploy Phase 4 gateway and sync snapshot)
- **M3: Architectural Documentation & Serving Engine Alignment** (Align docs with dual-llama.cpp reality)
- **M4: Observability, Operational Hardening & Vault Control Plane** (Appliance drift, alerts, Vault boundary)
- **M5: End-to-End Release Qualification & v1.0.0 Tagging** (Release gates, drills, formal tagging)

- **Scope**:
  - Remediate `yaml[empty-lines]` at `observability/prometheus/rules/aihost.rules.yml:186`.

### Milestone M1: Fleet Topology & Hardware Scope Decoupling
- **Objective**: Establish honest infrastructure boundaries by scoping v1.0.0 to the physically verified `ai-5820-01` host.
- **Scope**:
  - Remove `ai-p620-01` from `production`, `inference`, `gpu`, and `monitoring` children in `inventory/production/hosts.yml`.
  - Create `uncommissioned_hosts` group in `inventory/production/hosts.yml` containing `ai-p620-01` with explicit documentation.

- **Entry Criteria**: M0 complete.
- **Exit Criteria**: All production playbooks execute target resolution cleanly; `make syntax` runs with zero warnings across all 17 playbooks.
- **Responsible Role**: Infrastructure Architect
- **Relative Effort**: Low (2-4 hours)
- **Uncertainty**: Low

## 3. Post-v1.0.0 Evolution & Deferred Work

The following items are explicitly **excluded** from v1.0.0 and scheduled for post-v1 releases:

| Feature / Initiative | Target Release | Rationale for Post-v1 Scheduling |
|---|---|---|
| Physical commissioning of `ai-p620-01` | `v1.1.0` | Dependent on physical workstation availability and network rack commissioning. |
| Multi-node cluster orchestration (Ray / Fleet API) | `v1.2.0` | Single-node appliance meets all current engineering assistant throughput requirements. |
| Automated CMDB export & ITSM approval webhooks | `v1.2.0` | Enterprise ITSM integration requires external service endpoints currently absent in homelab. |
| In-engine SYCL kernel-level trace propagation | `v1.3.0` | Upstream llama.cpp SYCL engine does not currently expose OpenTelemetry span injectors. |
| Dual-GPU tensor-parallel split across cards for 70B+ | `v1.3.0` | Dual TP=1 independent workers provide superior concurrency and lower latency for 30B-class models. |
