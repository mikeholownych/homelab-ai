# Workstream B: Repository-Scale Investigation Report
## Autonomous Engineering System — Phase 10

### 1. Overview and Invariants

The `RepositoryScaleInvestigator` extends autonomous repository investigation from isolated single-file lookups to deep, multi-module architectural discovery. Every investigation finding generated by the investigator must be strictly grounded with immutable `SourceCitation` records referencing verified line numbers, file paths, and commit hashes:

$$\text{InvestigationFinding} \implies \forall c \in \text{citations}, \; c.\text{file\_path} \in \text{Repo} \land c.\text{line\_number} \in [1, N]$$

Hallucinated symbol citations, ungrounded architectural conjectures, and unstated assumptions are rejected at generation time.

### 2. Implementation Architecture

The investigator operates directly upon the `RepositoryKnowledgeGraph` and exposes:
1. **Bidirectional Dependency Tracing**:
   - `upstream_dependencies`: Complete list of modules imported by the target module.
   - `downstream_dependents`: Reverse-lookup of all modules that import the target module.
2. **Change-Impact Analysis**:
   - Input: A list of proposed file modifications.
   - Output: `ImpactAnalysisResult` enumerating directly affected symbols, downstream modules, associated regression tests, and risk classification (`LOW`, `MEDIUM`, `HIGH`).
   - Risk is automatically classified as `HIGH` if more than 5 downstream modules or more than 3 files are altered.
3. **Structured Investigation Reports**:
   - Emits `RepositoryInvestigationReport` containing categorized findings (`ConfidenceLevel.HIGH`, `MEDIUM`, `LOW`), exact citations, and architectural boundaries.
